# План R7.3 — регулярные объявления и новости в Pro-канале

Статус: **черновик для утверждения владельцем**.

## 1. Подтверждённое текущее состояние

- Production остаётся на R6 и не содержит периодический Pro reconciliation из R7.1. Поэтому пропущенные или ранее рассчитанные `CONTACT`/`INSPECT` не восстанавливаются в Pro автоматически.
- R7.1 уже реализован и проверен в staging: текущие подтверждённые решения создают стабильные PublicationEvent/outbox без дублей.
- Плановый content job публикует Market Pulse и `MARKET WATCH` только в Free-канал.
- Проверяемые автомобильные новости доступны только по запросу пользователя в личном чате бота.
- Автоматической публикации новостей в Pro-канал сейчас нет.

## 2. Цель

Pro-канал регулярно получает два разных типа контента:

1. полные инвестиционные карточки только для текущих подтверждённых `CONTACT`/`INSPECT`;
2. свежий англоязычный Dubai/UAE automotive news digest с активными ссылками на первоисточники.

Отсутствие нового подходящего объекта не считается ошибкой. Канал поддерживает активность новостями, но новости не подменяют инвестиционные сигналы.

## 3. Публикация объявлений

- использовать утверждённый R7.1 reconciliation;
- запускать его в начале каждого content job;
- стабильные publication/delivery IDs запрещают повторную публикацию одного решения в той же версии;
- `pending` можно повторно поставить в очередь, а `sent`, `sending`, `unknown` и `failed` автоматически не дублируются;
- в Pro идут только объекты, повторно прошедшие freshness, semantic verification, comparable, ROI/profit и risk-фильтры;
- карточка содержит фотографию, цену, рынок, max purchase, расходы, прибыль, ROI, confidence, риски, аналоги и ссылку.

## 4. Публикация новостей

- исходные данные: только настроенные HTTPS RSS/Atom feeds с publisher, датой и прямой ссылкой;
- отбрасываются старые, неполные, дублирующиеся и не относящиеся к Dubai/UAE automotive market материалы;
- semantic fingerprint строится из canonical URL, publisher и даты публикации;
- одна статья не публикуется повторно в той же content template version;
- digest содержит 1–3 свежих материала и публикуется только при наличии хотя бы одного валидного источника;
- при недоступности источников бот ничего не выдумывает и не публикует ложную заглушку в канал.

## 5. Генеративная модель

Vertex AI разрешён только для краткого англоязычного вступления и объяснения значения уже подтверждённых материалов для покупателей автомобилей в Dubai/UAE.

Модель получает только заголовок, publisher, дату, URL и извлечённый текст подтверждённого материала. Она не создаёт цены, статистику, даты, цитаты или события, которых нет во входных данных. Итог проходит проверку ссылок и фактических сущностей. При ошибке модели используется детерминированный digest без генеративного текста.

## 6. Управление в Admin Web

В Settings добавляются несекретные параметры:

- `pro_deals_enabled`;
- `pro_news_enabled`;
- `pro_news_max_items` (1–3);
- `pro_news_min_interval_hours`;
- `pro_news_ai_summary_enabled`;
- список установленных news feeds через отдельный проверяемый registry.

В Publications показываются last run, selected/created/sent/pending/failed отдельно для Pro deals и Pro news, preview следующего digest и кнопка безопасного idempotent run.

## 7. Staging и выпуск

- отдельная Firestore staging database;
- отдельный staging publisher;
- delivery и WhatsApp выключены;
- fixture подтверждает одну Pro deal publication и один news digest без дублей при повторном запуске;
- preview показывает фактические ссылки и итоговый английский текст;
- production deploy выполняется только после release evidence, ручного подтверждения владельцем и отдельной команды.

## 8. Критерий готовности

После production cutover плановый content job автоматически восстанавливает пропущенные Pro-сделки и публикует только новые проверенные news digests. Admin Web показывает и управляет обоими потоками без командной строки.
