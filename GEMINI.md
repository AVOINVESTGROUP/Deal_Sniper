# Интеграция Vertex AI Gemini

## Назначение

Gemini используется только как enrichment-слой после сохранения новой версии объявления и дешёвой предварительной фильтрации.

Допустимые задачи:

- извлечение комплектации и признаков повреждений из неструктурированного текста;
- классификация текстовых risk flags;
- краткое объяснение уже рассчитанного решения.

Gemini не определяет окончательную рыночную цену, не рассчитывает расходы, прибыль, ROI или максимальную цену покупки и не принимает решение вместо детерминированных движков.

## Платформа и библиотека

- платформа: Gemini API в Vertex AI;
- Python SDK: `google-genai`;
- проект, регион и имя модели задаются конфигурацией Cloud Run;
- модель не фиксируется в коде и выбирается из поддерживаемых в целевом регионе;
- production-аутентификация выполняется service account Cloud Run через Application Default Credentials;
- `GEMINI_API_KEY` и service account JSON в production не используются.

Локальная разработка использует Application Default Credentials через Google Cloud CLI. Секреты внешних сервисов, если они появятся, хранятся в Secret Manager.

## Предотвращение повторных вызовов

До обращения к Vertex AI объявление должно быть сохранено в Firestore. Ключ enrichment формируется из:

- `listing_id`;
- `content_hash` версии;
- версии prompt;
- имени модели;
- версии выходной схемы.

Если результат с таким ключом уже существует, повторный вызов запрещён. Retry одной Cloud Task не должен создавать второй запрос к модели после успешного сохранения ответа.

## Structured Output

Ответ должен соответствовать отдельной Pydantic-схеме enrichment, которая содержит только извлечённые признаки, confidence, risk flags и объяснение. Финансовые поля `market_price`, `repair_estimate`, `profit`, `roi` и `max_purchase_price` в схему LLM не входят.

Сохраняются:

- структурированный результат;
- версия prompt и схемы;
- имя модели;
- время выполнения;
- идентификатор исходного снимка;
- токены и оценка стоимости, если доступны;
- ошибка последней попытки без чувствительных данных.

## Требования к prompt

Prompt получает текст автомобильного объявления с фиксированной ценой и уже известные нормализованные поля. Модель должна:

1. извлечь только признаки, явно присутствующие или осторожно выводимые из текста;
2. разделить факт и предположение;
3. вернуть confidence для неочевидных полей;
4. обозначить признаки ДТП, затопления, повреждения шасси, проблем документов и import/non-GCC;
5. не придумывать отсутствующий VIN, сервисную историю, комплектацию или состояние;
6. не использовать собственные знания как источник текущей рыночной цены.

Объяснение для Telegram создаётся из детерминированного `DealDecision` и извлечённых risk flags. Числа в объяснении передаются модели как готовые значения и после ответа сверяются с исходным решением.

## Безопасность и наблюдаемость

- service account получает только необходимые роли Vertex AI и доступ к нужным документам Firestore;
- prompt и ответ не должны содержать Telegram token, секреты источников или служебные credentials;
- логи Cloud Logging не должны сохранять персональные данные продавца без необходимости;
- на число запросов, токены, ошибки и стоимость настраиваются метрики и бюджеты;
- при недоступности Vertex AI финансовое решение сохраняется, а объяснение получает статус `enrichment_pending` или `enrichment_failed`.
